A speed release of the open graphics stack for the PowerVR SGX545 in Intel's Cedarview
Atoms (N2600, N2800, D2500, D2550, D2700), the Intel Atom CE5300, and Intel's Clover Trail
(Atom Z2760). It fixes the slowdown 0.2.2 brought, is faster than 0.2.1 was, and adds a
32-bit kernel for Cedarview machines whose BIOS turns 64-bit off. Thanks to danilolc,
canteroman and SoNickRND for tracking the slowdown down, to MaiMorii for testing the 32-bit
packages, and to servidorjarvis1-svg and thesame for their fixes.

**Upgrade the kernel, the firmware and Mesa together, then restart.** The main fix is in the
kernel driver, so this release comes with a new kernel package. The interface between the
kernel driver and Mesa hasn't changed, so 0.2.3's Mesa also runs on the 0.2.1 and 0.2.2
kernels. If you went back to the 0.2.1 kernel and held it with `apt-mark hold`, release the
hold first:

```bash
sudo apt-mark unhold linux-image-7.3.3-sgx linux-headers-7.3.3-sgx
```

## Faster

- **The 0.2.2 slowdown is fixed.** The kernel driver ignored the GPU's interrupts on
  Cedarview and the CE5300, so every job waited for a timer to notice it had finished. On a
  CE5300 board, a submit took about 2,040 µs instead of 0.2.1's 215 µs. Testers saw it as
  desktop lag and about 5% lower game frame rates. It's back to 0.2.1's speed.
- **No more CPU cache flushes for the screen's buffers.** The buffers gma500 shares with the
  GPU are never cached by the CPU, so flushing them before and after every job was wasted
  time. With the flushes off, danilolc measured OpenArena's timedemo at 51 FPS instead of 46.
- **Less CPU per draw:** about 6% faster in OpenArena's timedemo.
- **4x multisampling** resolves on the GPU instead of copying every frame on the CPU: a simple
  scene at 1024x600 goes from 22.7 to 98.1 FPS (issue #43, found by danilolc).
- **Draws that one call splits** are merged into one, which helps games that draw in immediate
  mode, like Counter-Strike 1.6.

## 32-bit Cedarview

Some Cedarview netbooks, such as the HP Mini 110-4300, have a BIOS that turns the CPU's
64-bit mode off. This release has 32-bit (i386) packages for them: the kernel, the
firmware, and a `mesa-sgx:i386` that now also installs on a 32-bit system by itself.
docs/INSTALL.md, "Cedarview without 64-bit mode", has the steps. Debian 13 has no 32-bit
installer, so you install Debian 12 first and upgrade it.

## Fixed

- **OpenArena and ioquake3 with `r_PreferOpenglES 1`:** white walls.
- **Mipmapped textures sampled at a coordinate the shader computes** took the wrong level
  along the diagonal where two triangles meet, in 2D textures and in cube maps.
- **Depth textures set to repeat** were clamped instead.
- **Partial color masks** were ignored by the CPU copy path.
- **Imported video frames:** 8- and 16-bit planes sample correctly.
- **Imported buffers** were sometimes kept after their last user exited, until the GPU had
  other work (found and fixed by thesame).

## OpenGL ES 3.0 work, off by default

These are steps toward OpenGL ES 3.0. They're behind `SGX_DEBUG` switches and don't change
anything unless you turn them on: sRGB render targets, the ES 3.0 texture formats (float,
half-float, snorm, float depth), `textureLod` and `textureGrad`, vertex texture fetch, 3D
textures up to 256 deep, and occlusion queries. Most of this work is by servidorjarvis1-svg.

## Upgrading

**From 0.2.x, with the apt repository:**

```bash
sudo apt update && sudo apt upgrade
```

Then restart. On a 64-bit system with the 32-bit Mesa (`mesa-sgx:i386`), `apt upgrade`
updates it too.

**From 0.1.x or from test builds:** see the 0.2.0 notes, "Upgrading", and install 0.2.3
instead of 0.2.0.

**CE5300 (DKMS), Clover Trail, and Cedarview with DKMS:** rebuild the driver from this
release's source as in docs/INSTALL.md, section 2.

## Tested

- **On CE5300 boards**, with the 0.2 kernel and its open microkernel:
  - the submit time, before and after the fix;
  - **dEQP-GLES2**, the whole mustpass list, on this release's kernel and Mesa: 16,649 pass,
    70 expected failures, no new failures (0.2.2: 16,637 and 82);
  - the Mesa test suite in CI for every change.
- **On Cedarview:** an N2600 netbook on 32-bit Debian 13 with the 32-bit test build: the GPU
  and its open microkernel start, and Counter-Strike 1.6 runs at 18 to 50 FPS, against 3
  without the GPU.
- **In CI:** the 32-bit kernel boots in QEMU and loads both drivers; a fresh 32-bit
  install, the upgrade from 0.2.2 on 64-bit, and the DKMS build against both kernels' headers.

## Known issues

- **No OpenGL 3.x or OpenGL ES 3.0 yet** by default. Chrome and Firefox fall back to software
  rendering, and PPSSPP and DuckStation need it.
- **Luanti 5.10** freezes the desktop when a world loads.
- **Minecraft 1.16.5 with OptiFine or Sodium** crashes on start for one tester.
- **Red Eclipse** draws maps only in parts and hides other players: occlusion queries always
  return 0, so the game culls what it should draw (found by danilolc).
- **GTA Vice City (reVC)** crashes when the game starts, and **Half-Life: Source and Portal**
  show a black screen.
- **On a 32-bit kernel**, the GPU's memory comes from the first 896 MiB of RAM, which the
  kernel needs too. If programs get closed for lack of memory, lower `SGX_SLOTS` as
  docs/INSTALL.md describes.

Please report problems on the issue tracker, with your computer model and the output of
`sudo dmesg | grep -i -E 'powervr|gma500|drm'` and `glxinfo -B`.
