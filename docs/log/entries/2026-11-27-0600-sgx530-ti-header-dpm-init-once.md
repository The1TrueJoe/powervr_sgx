# SGX530: the full register header and the SGX535 driver's DPM init, tried on the board

**2026-11-27, 04:35 to 04:50 UTC. The OMAP3630 test board, under lock, a fresh software reboot
before every run. Released clean afterward.**

## Sources (L)

Joseph cleared two more sources on 2026-11-27, for reference only. Facts from them are
leads (**L**) until the board confirms them. No code, tables or header text from either is
in this repository.
- **TI's SGX530 register header.** It's the full autogenerated `sgx530defs.h`, rev 1.15 of
  2006-07. Unlike the GPL kernel headers (K), which list only what the host touches, it
  names the TA, DPM, ISP, PDS and VDM registers too.
- **img-sgx, a public SGX535 driver (GPL-2.0).** Its kick, init and heap-load sequences are
  transcribed from a closed driver, so they are treated as static facts. Shipping code
  doesn't depend on them until hardware confirms them.

## What the header says about the DPM on the SGX530 (L)

- **Page numbers are 14 bits.** That holds in every free-list head, tail and previous
  field, and in the page counts and thresholds. The SGX545's are 16. So a PB the DPM can
  index is at most 0x4000 pages (64 MiB) from the requestor base.
- **The PB descriptor's registers:**
  - 0x618/0x61c: the TA page-table base, and the TA free list (head b0-13, tail b16-29).
  - 0x648: the TA's previous page (b16-29).
  - 0x620/0x624: the TA and ZLS page thresholds.
  - 0x628: the TA global list (size b0-13, policy b16).
  - 0x638: the start of the context's pages (local b0-13, global b16-29).

  These are the registers our microkernel's PB load writes, with the same meanings.
- **The PDS page threshold is 0x614 on the SGX530.** Our microkernel writes it to 0x668,
  the SGX545's offset, which the SGX530 doesn't have.
- **Absent on the SGX530:**
  - 0x664 (the SGX545's free-list selector, which we write as 3), and 0x668;
  - the host alloc and dealloc lists, and their loads 0x688/0x690.

  `EVENT_STATUS2` has only the TA and 3D free-list loads (b0, b1) and the TA, 3D and DL
  triggers (b4, b3, b2).
- 0x6a8 is `DPM_TA_EVM`, b0 INIT; its done event is `EVENT_STATUS` b22. Also named:
  - 0x6a0 (free context now), 0x6a4 (3D timeout now);
  - 0x658 (partial render enable), 0x65c (the partial-context load/store operation);
  - 0x63c (3D deallocate), 0x640/0x644 (single-page alloc/dealloc);
  - 0x734 (which unit is requesting pages), 0x738 (region-header parser idle).
- 0x200 is `VDM_START`, and 0x238 is the VDM control-stream base. 0x274 is `TE_STATE`, and
  0x330-0x358 are the VDM context-store registers.
- 0x218 (`TE_PSG`):
  - b18: force a new state;
  - b19: pad with zeros;
  - b20/b21: Z store/load;
  - b22: complete on terminate;
  - b23: Z-only render;
  - b24: enable context state restore.

  Our microkernel always sets b24.

## What img-sgx does at the TA (L)

- **The heap load, once.** It writes each list's page-table base, then its free list as
  last page << 16 | first page, then the previous page, then the thresholds. Then it
  pulses the list's load register. The first page is the heap's page number within its
  256 MiB region. It waits once for all the load bits in `EVENT_STATUS2`. Then, the first
  time only, it sets 0x6a8 = 1 and waits for b22.
- **INIT once per boot.** By its own measurement on the SGX535, the DPM refuses a second
  INIT after the first. A module reload or a soft reset doesn't clear that, and a warm
  reboot does. It also writes no 0x664.
- **The TA kick:**
  1. 0xc90;
  2. `PDS_INV1`, waiting for 0x138 b2+b6;
  3. `PDS_INV_CSC`, waiting for b0;
  4. 0x804 b28, waiting for b26;
  5. 0xa08 = 1;
  6. 0x200 = 1.
- **The state task, in value mode.** The PDS DMAs the state block into the primary
  attributes, a `mov o, pa` copies it out, and one emit hands over the count.

## Tried on the SGX530 (C)

These used the pointer-mode clear-only recipe of 2026-11-27-0430 and the probe_a74 =
0x05208200 driver, with scratch microkernel switches (not committed). Every run started
from a fresh boot, so each INIT was the first since power-up.

| run | change | result |
|---|---|---|
| 1 | INIT once: after the TA list load, 0x6a8 = 1 and a wait for b22, skipped when b22 is already set; no 0x664 | both waits complete, no timeouts. The TA hangs as before: `EVENT_STATUS2` 0x10 (TA triggered), 0x700 = 0x10210000 unmoved, 0x724 = 0, 0x734 = 0 (nothing asks the DPM for a page) |
| 2 | 1, with the PDS threshold written to 0x614 (not 0x668) | the same |
| 3 | 2, with 0x218 = 0x00400000 (b22 alone; reads back so) | the same |
| 4 | 3, with the TA side invalidating through `PDS_INV1` and waiting for 0x45 | the wait completes; the same hang |
| 5 | 4, with a value-mode state task (`SGXGEN_EMIT530=state1`, no state pointer) | **fault at 0x0000d000, requestor b1**: the state header is taken as an address, as on 11-15 |

So on the SGX530, none of these gets the TA to ask the DPM for a page:
- the DPM INIT handshake, done once after a fresh boot;
- the 530's own PDS-threshold offset;
- `COMPLETEONTERMINATE`;
- the SGX535's TA-side invalidate.

Value mode still fails: the MTE takes the first emitted word as the state's address. The
hang sits before the DPM: the TA is triggered, and no page request ever reaches the DPM.

Two notes on the method:
- These were software reboots. img-sgx found that a warm reboot clears the once-per-boot
  state on the SGX535, so a power cycle wasn't asked for.
- 0x614 isn't in the driver's register read list, so run 2's write is checked only in the
  image, not read back.

## What follows (D)

- The PB load on the SGX530 should write the PDS threshold to 0x614 and skip 0x664/0x668,
  which the header doesn't name. That's a fix to `ukernel/cores/sgx530.py`. It showed no
  difference on the board, and nothing regressed.
- The header's VDM registers (0x200 `VDM_START`, 0x238, the context-store block) say the
  SGX530's TA front end is a VDM fed by a control stream, as on the SGX545. The hang before
  any DPM request is in the VDM/MTE stage. That part of the header is the next thing to
  read against what our stream does.
