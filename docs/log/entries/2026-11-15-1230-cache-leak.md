# The buffer cache's lost references (shared memory grew ~2 MB/s on Minecraft's title screen)

2026-11-15, a CE5300 board, RAM boot of the v0.2 CE5300 kernel and its open
microkernel; Xorg (modesetting on simpledrm, glamor) in a Debian root with the packaged
mesa-sgx 0.2.1; the normal boot restored after each run. Mesa x86_64-x11 from dev
eecb6e0f with the fix, staged in the root's /opt/sgx for the runs that say so.

**Cause:** the winsys's cache of freed buffers (d5617743, in 0.2.0 and 0.2.1) takes a
buffer whose free dropped its last reference, and the allocation that took it from the
cache handed it out with no reference. The next free took the count below zero, found
it non-zero and returned: the buffer was neither cached nor closed, so it stayed
until the process exited. Every buffer the cache gave out leaked on its next free.

- **Minecraft 1.7.10** (vanilla, LWJGL 2, desktop GL 2.1), sitting on its title screen
  at 720x480, ~9.5 FPS, 4 minutes a run:
  - 0.2.1: the game's powervr_sgx memory (its DRM fdinfo) went from 190 to 588 MB
    between minutes 1 and 4, ~2.2 MB/s, ~230 KiB a frame; the system's Shmem with it;
    its RSS and RssShmem stayed flat (the buffers aren't mapped), and so did Xorg.
  - `SGX_DEBUG=stats` with the GEM counters (92056219): live GEM objects up ~27 every
    16 s, each 1280 KiB (a 1 MiB vertex buffer's device copy and spare page in its
    size bucket), with ~4 allocations a 2 s report, 3 of them from the cache, and
    almost none closed. No zombies or cached bytes piled up.
  - The fix: 117 MB through all 4 minutes, Shmem flat, 29 to 31 live GEM objects with
    buffers made and closed in step.
- **`mesa/tests/sgx_copyleak`**, 400 frames: a new 1 MiB vertex buffer a frame after
  the last one was deleted and the GPU waited for (so the cache gives its copy out), a
  depth buffer:

  | Window | 0.2.1 | Fix |
  |---|---|---|
  | GLX under Xorg | 640 KiB a frame, FAIL | 0.0, PASS |
  | EGL on a GBM surface | 640 KiB a frame, FAIL | 0.0 (0.1 Shmem), PASS |
  | GLX, 7 copies a frame (the title screen's) | | 0.0, PASS |
  | GLX, no new buffers | | 0.0, PASS |

  The first version gave one buffer new contents each frame instead. Under X, 0.2.1
  didn't leak with it, because the buffer kept its device copy and nothing went through
  the cache. On the GBM window it leaked 646 KiB a frame (0.0 with the fix). The test
  now deletes the buffer, so the cache is used on both.
- No job timeouts, page faults, WARNs or BUGs.
