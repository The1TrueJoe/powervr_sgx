# GL3 work: OpenGL ES 3.0 first, then GL 3.1

2026-11-16. Decision (Joseph): "both but lets try for es3". OpenGL ES 3.0 is the first target and
desktop GL 3.1 the one after it; GL 3.2 stays unplanned.

Why: Firefox turns on hardware WebRender on Linux only with desktop GL ≥ 3.2 or GLES ≥ 3.0 (Mozilla
bug 1748819 comment 4, as cited in issue #16). Chromium's GPU process needs an ES 3.0 context, or
desktop GL ≥ 3.2 through ANGLE's GL backend (issue #16, not checked here). GL 3.1 reaches neither.

Mesa 26.2.5's ES 3.0 gate (`compute_version_es2()`) against dev's caps, with what the gate doesn't
check, is in `docs/GL3.md` "OpenGL ES 3.0". Most of the work is shared with GL 3.0/3.1. Only ES 3.0
needs: 3D textures ≥ 256, `essl_feature_level` 300, depth cube maps and three sampling formats. A
contributor with a Clover Trail tablet offered to work on the ES 3.0 gap. Contributions go in as small
PRs on dev, one feature each, behind its own cap.
